# Qualification facts and parent-only locking

Use for restart-qualification projections, current-scope construction or failed-
candidate locks. Read active-repo docs/QUALIFICATION_CANDIDATE_FACTS_DESIGN.md,
research and outcome, plus [bounded qualification](bounded-restart-qualification.md).

1. Trace actual policy inputs before dropping detail. Qualification retains failed
   id/status/search; queue/legacy recipient IDs, profile and numeric floor; fallback
   mode/target/floor; track scopes/participants; shared-discovery marker; request
   source request/owner. Current review/conflict facts still use canonical SQL.
2. Preserve missing versus JSON null, legacy nullish precedence, scalar/array
   values and presence-based refusal. Do not strip nulls or copy a failed context's
   consent into a new candidate. Keep valid shared-track ownership and catalog
   verification; snapshots or context equality alone do not grant authority.
3. Project known keys in SQL before Node allocation. No full provider payload,
   file/decision rows, peer/path or unrelated prepared-add file-count query on the
   qualification boundary. Required context arrays remain variable, and PostgreSQL
   may still decompress stored JSONB; result width is not physical I/O or RSS proof.
4. Reuse the shared policy reader and current-scope guard factories. Qualification
   injects the minimal projection and parent-only FOR UPDATE. Selection retains
   full facts/child locks. Qualification rejects selected-candidate input rather
   than silently accepting a different command scope.
5. Keep parent lock strength unless FK/publication producers are separately
   audited. NO KEY UPDATE permits KEY SHARE inserts; removing child enumeration
   does not authorize changing that boundary. Reread facts after a parent wait,
   preserve canonical lock order and take no candidate locks after the NOWAIT fence.
6. Pair real SQL full/minimal policy, search-requirement and progress-digest parity
   with malformed/legacy/consent/floor/valid-stale track cases. Reuse the shared
   fixture on guarded packaged PostgreSQL. Independently observe legacy child
   waits and parent mutation/delete/FK serialization. Use actual HTTP/queue proof
   for held child rows, parent-wait policy refresh and shared-track ownership.
7. Check existing bounded restart, selection, cursor/fence, browser and media lanes.
   Keep public status/focus/permissions unchanged; manual screen-reader/device
   proof remains separate. Adding a policy input requires updating this explicit
   projection and parity evidence in the same change.

Record serialized fixture bytes and cardinality without claiming latency, RSS or
whole-platform improvement. Read-only chooser/detail and selection still use
their existing full scope. Extending the projection to those boundaries needs
separate access, policy and presentation qualification.
