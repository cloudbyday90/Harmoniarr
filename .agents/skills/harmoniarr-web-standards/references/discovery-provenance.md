# Standards method for discovery through publication

Use when qualifying canonical search intent through response ingestion and
acquisition. Read the current [design](../../../../docs/NATIVE_DISCOVERY_COMMAND_DESIGN.md)
and [official-source tradeoffs](../../../../docs/NATIVE_DISCOVERY_COMMAND_RESEARCH_2026_10.md).

1. Identify fixture inputs separately from derived state. Saved monitoring and
   metadata may be controlled inputs; candidate rows cannot be seeded when the
   claim is real discovery ingestion. Let configured reconciliation derive wanted
   rows and shared discovery links; the worker reconciles them again.
2. Discover/open applicable official sources through MCP. W3C provenance guidance
   informs origin/version reporting; IETF governs HTTP semantics; OWASP informs
   object authority; database documentation explains current-state locks. Record
   date/status and label project inferences. Do not treat them as interchangeable
   certifications or permission for unrelated changes.
3. Trace Find matches through resolver, durable target intent, required audit,
   run coalescing and actual queue/worker completion. Prove same-key replay and
   distinct-key repeated intent separately. Preserve actor versus recipient and
   refuse invalid scope/CSRF/disabled state before provider traffic.
4. Feed bounded responses through the actual client/service and ingestion. Keep
   real scoring/quality/readiness policy; ambiguous equal sources can require a
   manual choice without replacing eligibility. Verify request/search/candidate/
   release/file correlation and refreshed canonical permissions.
5. Name transport evidence precisely. Owned HTTP responses qualify client and
   ingestion, not native server/peer search. The newer [native search method](native-search.md)
   uses actual queries and compressed peer messages for that boundary. Native file transport is a separate
   boundary; byte completion still precedes inspection and canonical publication.
   Retain runtime/source/hash identities and failed prototypes.
6. Await real worker completion and owned HTTP/provider/media cleanup. Keep this
   bounded scenario opt-in and fast pure controls in the routine lane. Browser
   submission/focus, public-network search and full decoding require other proof.

The [outcome](../../../../docs/NATIVE_DISCOVERY_COMMAND_OUTCOME.md) records executed
scope and the next incomplete boundary. This extends the existing standards skill;
it does not create a second operation or standards framework.
