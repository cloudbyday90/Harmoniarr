# WebP encoder boundary

Use for token-growth admission or structured native allocation investigation.
Read active-repo docs/WEBP_ENCODER_BOUNDARY_DESIGN.md, research and outcome.

- Match the installed native version and actual mapped file hashes before causal
  interpretation. Installing debug packages can upgrade libc; detect drift and
  restore the original mapped bytes in an isolated diagnostic image before
  repeating evidence. Package database labels alone do not establish identity.
- Use bounded private breakpoints/syscall evidence. Pinned stripped binaries may
  require verified call-site offsets and ABI layout; these are version/architecture
  specific and cannot become production addresses or error classifiers. Keep
  instrumented timing/peaks separate from normal qualification. Retire tracees,
  debugger/tracer and containers; preserve failed/invalid diagnostic attempts.
- Separate actual native enum, failed request and limit state from inference.
  Observe DATA, AS and mapping count at the failure, before cleanup reduces
  memory. Generic error text alone cannot identify an allocator or deadline.
- libwebp 1.6 token pages use a quality-dependent macroblock count and minimum
  size. Share production WebP settings with the additional growth reserve.
  One page plus allocator slack is a planning calibration, not a bound on all
  accumulated pages. Never increase caps or tune the pinned input to obtain a pass.
- The fixed 7120-square input now uses `rgb8-webp-7120-token-refusal`; the former
  admitted selector remains a CLI alias. Strict qualification requires only the
  21-byte memory frame, normal exit 1, no signal and no publication. Preserve
  the prior failed-publication evidence and current JPEG/medium-WebP successes.
- Pair exact/minimum-page/macroblock budget and pre-grant tests with fresh 2/3 GiB
  mixed profiles, affected native lifecycle/allocation/corpus/medium controls and
  one fast gate. Reuse fixed artifacts; retain unchanged SQL/browser/provider
  proof only after precise source/runtime comparison. No profile proves a minimum
  deployment budget, simultaneous peaks or universal accepted-image success.
