# Recipient-owned alternative selection

Use for Choose another match after measured quality refusal. Read the active
repository's docs/QUALITY_REVIEW_MATCH_DESIGN.md, research and outcome.

1. Trace the canonical release inspector, normalized permission, bounded choice
   projection, authenticated selection route, owning service and refreshed state.
   Reuse the chooser and command gate; selection must remain distinct from download.
2. Apply W3C APG disclosure behavior: native button, Enter/Space, accurate expanded
   state and controlled content. Keep disclosure focus and background refresh quiet.
   User-command feedback/focus belongs to the existing inspector owner.
3. Apply OWASP action-boundary authorization. Derive the recipient on the server,
   retain fresh session/CSRF/idempotency and recheck current actor privileges under
   account locks. A permitted read or an old offered choice is not write authority.
4. Reuse canonical account, wanted/discovery, apply-creation and candidate locks.
   Read current facts after waiting. Refuse changed search, disabled/fulfilled or
   unlinked participants, conflicting work and stale track scope.
5. Preserve the failed acquisition's shared quality floor plus stricter current
   policy. Require the alternative's own matching scope and policy; never copy
   consent or rewrite weaker candidate context. Advertised quality only permits
   trying a download; measured audio remains authoritative for library add.
6. Commit selection, event and required audit together. Advisory Activity follows
   commit. Keep failed evidence/files intact and create no transfer/apply work.
7. Prove current SQL/HTTP ownership, stale state, rollback, replay, actual lock
   waiting and concurrent alternatives. An observer connection must be independent
   of the bounded application pool; qualification must not manufacture pool famine.
8. Use the real app/API in browser checks for keyboard disclosure, scoped choices,
   feedback, Current status focus and reload. Keep manual screen-reader/device
   acceptance separate from browser semantics and synthetic search candidates.

Research official sources via connected search before citing URLs. Distinguish
normative requirements, informative W3C patterns and project-specific inference.
Prefer a narrow built-in owner over a second service or duplicated downloader.
