# Guarded workload selection and failure evidence

Use this reference for Wanted workload collection or a timeout diagnosis, not
ordinary styling/unit changes. Start from the actual CLI policy and benchmark
owners; do not use a selected measurement as a replacement for correctness tests.

Verify local ffmpeg/ffprobe or an existing owned media image before PostgreSQL
work. Capture its immutable identity/tool version and scope/restore the image
environment. Missing tooling is a prerequisite failure, not a database diagnosis.

`scripts/measure-wanted-guarded-workload.js` keeps the full default matrix.
For a smallest source comparison, use `--source-noops --profiles sine --bindings 2
--pairs 1`; for a failed largest noise case, select `--profiles noise --bindings 8
--pairs 1`. Supply `--expose-gc` and `--output <local JSON>`. Do not enlarge
dimensions, pool limits, checkout/scenario deadlines or scheduling to get green.

Version-two artifacts record full/selected scope, expected sample membership,
partial summaries, safe failure class/code/frames and the last approved
distinct-binding phase checkpoint. Await returned checkpoint sinks; diagnostic
failures must not replace benchmark work. A phase locates the current operation,
not its root cause. Server readiness and a replacement query are separate from
the original client's failure. Node TimeoutError is an approved timeout label;
messages, assertion payloads and private connection/source data remain excluded.

Retain Error/null, cleanup completion and every exact private result/durable/
digest comparison. Do not publish a lone unmatched sample if its comparator
failed. Keep historical, prerequisite-failed, full-replay and selected-native
collections separate. Work counts are structural; local timing/memory is
descriptive. See `docs/WANTED_WORKLOAD_REPLAY_OUTCOME.md` and its research/design;
the Wanted publication proposal still needs all-writer/absence proof.

Seed phase evidence: benchmark artifacts retain a 256-record approved tail with
explicit clipping, numeric nested spans and context. Read only nonoverlapping
phase durations when explaining cost. Actual inspections follow the active
context even when a shared service was constructed for the first context.
The default distinct fixture captures the actual worker preview; use
`--seed-preview separate` for the earlier preparatory path. Validate exact worker
plan/file/receipt/scope evidence and native helper callers before removing work.
Lazy command imports should refuse invalid input/missing GC before loading the
app. See docs/WANTED_SEED_PHASE_OUTCOME.md; a passing largest selection does not
diagnose an older timeout, and current inspection cannot become a cache.

For the read-only Docker inspection pilot, select `--media-execution owned` on
distinct/source workloads; per-command remains the default comparator. With no
image, local-tool behavior remains unchanged. Capture a complete acknowledged
container ID and verify effective image/root/mount/network identity. Close
admission, drain admitted startup/exec, and verify stopped state after a failed
exec before removal. Killing the host CLI is insufficient. Preserve Error/null
and retain the workspace after unknown creation or uncertain cleanup; the
functional app cleanup guard is per invocation. Verify the current
root identity again after owner removal; a replacement directory cannot inherit
cleanup authority. Audit reusable app fixtures' separate workspace owner before
adoption. Native tests must
prove changed-media reinspection, read-only mount denial and real held-exec
retirement. Keep every canonical inspection and private comparator. See
docs/OWNED_MEDIA_EXECUTOR_OUTCOME.md for the selected measurements and limits.

For owned transport cost, add `--media-diagnostics on` to the explicit owned
distinct/source workload; off is the default. Seventeen fixed operation phases expose
bounded counts and monotonic aggregate durations after actual close. Completed
CLI inspection does not certify configuration validation, and ownerCleanupSafe
does not certify whole-app drainage. Keep local-tools/no-owner summaries distinct,
invalid clocks untimed, clipped budgets explicit and original Error/null through
held optional sinks. Serial transport windows can be summed; overlapping seed,
caller queue and close windows cannot be added again. Exec time includes CLI/
daemon/codec/stdio, not just ffprobe CPU. Native invocation counts and exact
canonical comparisons precede interpreting a one-pair off/on timing. See
docs/MEDIA_TRANSPORT_PHASE_OUTCOME.md for the earlier twelve-phase CLI collection.

Select `--media-inspection api` only with the explicit owned workload and an
existing image; absent image refuses before PostgreSQL startup. CLI remains the
default. Resolve environment/context precedence, pin every CLI call to the same
local endpoint and privately match daemon/version before creation. Version-two
snapshots add bootstrap CLI/API phases and `docker_hybrid` summaries; total
operation counts are not all CLI launches. Prove bounded fragmented/oversized/
malformed/stalled/early-close/aborted responses, same-owner configuration checks,
canonical reader disposal and Error/null retention. Native API/CLI comparisons
need acknowledged stable states, including active ExecIDs and stopped state;
sequential reads across an unacknowledged start are not equivalent snapshots.
Keep changed-media, read-only denial and actual exec-timeout retirement controls.
Use reversed-order selected canonical comparisons, preserving exact results,
receipts/digests/bytes and resource bounds. Small successful samples do not
diagnose old largest-profile failures or prove Linux socket/whole-CI behavior.
See docs/MEDIA_INSPECTION_API_OUTCOME.md before broader or default adoption.

The largest API selection now has a completed noise/eight-binding/one-pair
collection; retain old incomplete collections as unresolved history, not a
matched speed comparator. `test/integration/media-linux-socket.test.js` is an
explicit native lane requiring an existing media image and immutable
HARMONIARR_INTEGRATION_LINUX_READER_IMAGE. Its trusted runner receives the actual
Unix socket and a minimal private bundle, never host credentials or production
mounts. A read-only socket bind still grants privileged daemon access. Compare
private daemon identity and acknowledged running/active-exec/stopped snapshots,
seal/drain readers and verify whole-runner retirement before workspace deletion.
Unknown creation or failed cleanup retains that workspace. This proves Linux
socket reads on the observed daemon, not Linux media path/lifecycle deployment
or whole-CI speed. See docs/MEDIA_API_SCALE_OUTCOME.md; audit reusable scenario
and outer cleanup owners before executor adoption there.

Await both applicable predicates and actual isolated-database completion before

later release failure, keep safe artifact retention distinct from refusal and
recheck canonical parent/child directory identity before recursive removal.
