# Wanted distinct private binding profile design

Date: 2026-10-13. Scope: explicit local workload measurement and native fixture
proof. No production authorization, hash, pool, schema, retry or release changes.

The existing guarded benchmark grows duplicate receipt history over two files.
That establishes repeated-receipt costs, but cannot characterize growing physical
file, saved requirement and monitored-context work. Add a separate opt-in
`--distinct-bindings` profile to the existing measurement CLI.

## Fixture and measurement owners

Create 2, 4 or 8 distinct private file bindings, owned by two fixed users across
1, 2 or 4 disjoint artist/release contexts. Each owner saves one supported typed
track requirement per context through the canonical save and reconciliation
worker. Each two-owner candidate receives real tagged FLAC files and executes
the existing actual apply worker to completion/close. No fabricated delivery
receipt substitutes for that first apply.

After delivery, copy each candidate's fulfilled evidence into two additional
applied candidate histories. Three receipts per physical binding are an explicit
fixture dimension, not three fresh deliveries. Growing contexts is necessary to
exercise independently eligible exact closed groups; mixed requirements within
one artist retain their existing conservative behavior and are outside this
profile. Requirement means the saved owner/release/scope binding; satisfied
requirements need not remain as active Wanted rows.

Separate narrow ESM modules own additional consent/catalog contexts, candidate
media/apply, binding inventory/assertions and orchestration. Reuse the existing
first two-owner fixture, guarded profiler and rollback-owned client. Inspect
distinct real paths and device/inode pairs, current saved scopes, two owners,
release contexts, historical receipt counts and actual byte sizes before timing.
Output only fixed counts/sizes/memory/timings; keep IDs, roots, paths, scopes,
projection digests and full DTOs private.

Compare member and bounded current-root modes on one borrowed connection with
a fresh rollback transaction per sample. Both obtain the same authority proof,
perform both full hashes and retain every publication/event recheck. Compare
complete results and private projection digests before emitting either sample.
At B bindings and R=3 historical rows each, the current satisfied-source contract
performs P=B+5 projections: four publication reads plus B source guards and a
final source guard. Assert PBR available receipts, 2PB full hashes, 2P times the
sum of actual file bytes; member roots 2PBR, bounded roots 2PB. General non-root SQL also grows with saved
contexts, so do not carry over the old fixed 160-query expectation.

Use two alternating pairs per tonal/noise cardinality (24 samples). Real media
setup, GC and rollback are outside service elapsed work. The workload remains
explicit; ordinary test discovery gets a bounded four-binding native scenario
with rollback, late-byte refusal and required-event rollback proof. Keep serial
fixture use, existing two-client/10-second checkout and scenario deadlines.
Own returned worker/query/media completion through cancellation and cleanup.

## Options and recommendation stack

| Option | Pros | Cons | Decision |
| --- | --- | --- | --- |
| More duplicate receipt rows over two files | Cheap existing comparator | Does not grow real file/context work | Retain separately |
| Canonical distinct deliveries with fixed history | Real authority, paths, hashes and context scaling | Setup grows; covers disjoint contexts rather than all library shapes | Implement |
| Copied files / fabricated primary receipts | Faster preparation | Bypasses delivery and current consent evidence | Reject |
| Shared positive cache / fewer guard hashes | Could reduce measured work | Requires a new authority and mutation contract | Defer; no permission from timings |

Recommended stack: canonical bounded fixtures, actual guarded exact-work
comparisons, private monotonic/process-memory observations, then evidence-backed
optimization at the measured dominant owner. Per-source guards reread all bindings,
so hash/root work also grows with projection count. Sampled memory is not a cap or
allocation attribution; two observations are local descriptive evidence.
