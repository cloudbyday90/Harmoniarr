## Implemented boundaries

The separate root-read policy/store/service verifies the current held projection
key, transaction identity, origin/Read Committed mode, enabled unconditional
statement triggers, protected columns and exact invoker/function/config contract.
An opaque token lives only during the owning callback and binds its queryable.
Registry entries contain transaction identity, never root values; finally deletes
them after success, Error or null. Closing work rechecks token lifetime before
roots and after its full hash. Fabricated, copied, mismatched or expired tokens
cannot select the reduced root budget.

Canonical root-context SQL validates transaction identity even when the owner is
absent; the sentinel join preserves the prior null-owner DTO. Two independent
current statements resolve opening/closing roots, including filesystem containment.
Within-transaction root/disabled/null changes still refuse closing positives.
Transaction identifiers never enter Wanted sources, digests or saved summaries.

The default publication service selects bounded mode. Custom projections default
to compatibility mode; standalone readers have no grant and custom root resolvers
always keep member reads. Explicit controlled fingerprint wrappers still need
the real grant and canonical root resolver. Member comparator mode obtains the
same proof but withholds its token. There is one proof statement per admitted
comparison sample, so query savings measure root work rather than changed guards.

The original exact JSON/group budgets, serial negative/mixed/unsupported fallback,
opening/closing file evidence and all seven production rechecks remain. Runtime
guard failure refuses reduced authority. No migration, dependency or root cache.
Two fixed observer counters distinguish bounded groups/rows without identifiers.

## Recommendation and next work

Adopt the bounded positive path only inside the proved publication contract.
Its benefit is fewer root queries/containment calls while keeping identical
current bytes and outcomes. Its cost is runtime proof/identity plumbing and the
existing global writer wait; no preemption, host-file immutability or universal
performance/security claim follows. Standalone/custom readers stay conservative.

Recommended stack: writer admission → runtime transaction/guard proof → scoped
token → exact bounded group → current opening root/hash → current closing root/
hash and scope/source comparison → original publication/event transaction.
Next, instrument the original cold client's connection/startup stages and verify
its target against acknowledged fixture configuration, using fixed private
observations and the correlated checkout record. Keep limits unchanged and then
complete missing noise profiles during a quieter window. A later healthy probe
or control cannot diagnose that failure. Before broadening grouping, measure
distinct bindings and remaining byte/projection/heap costs; the noise control's
fingerprint phase now dominates its bounded sample.
