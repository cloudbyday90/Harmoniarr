# Role-aware search correction design

Date: 2026-10-20. This follows the [count outcome](MISSING_SEARCH_COUNTS_OUTCOME.md).
See the separate [research](MISSING_SEARCH_CORRECTIONS_RESEARCH_2026_10.md).

Canonical Missing Music currently explains recorded zero-candidate ingestion with
bounded response/file counters but gives no usable destination for its causes.
The actual ignore-list and connection APIs require an administrator, even though
the router admits some other roles to their page shells. Recipient ownership of
a release does not grant ownership of these household-wide settings.

Extend the existing diagnostic policy with two presentation capabilities derived
from the authenticated actor, an active recipient and validated current counters.
Only an administrator reviewing an active recipient can receive a cause-specific
review capability. Keep disabled-account history without correction links.
Preserve these strict booleans through the existing detail composable.

A focused pure ESM presenter maps ignored-source evidence to the named
`activity-ignored` route and malformed-file/missing-identity evidence to
`settings-connections`. Other actors receive administrator guidance. Unknown or
missing capabilities deny links. Reuse the bounded Settings return context for
the selected decision; never accept a provider-supplied URL or query parameter.
The ignore page keeps its existing navigation; this change adds no return flow.

The small existing diagnostic component renders semantic list items and native
router links with meaningful names, visible focus and mobile-sized targets.
Explain that ignore changes affect future searches for everyone. Malformed
responses justify investigation without diagnosing a broken connection. Do not
invent a title-term editor or change policy/quality/search eligibility.

Opening a review destination performs no source-policy mutation or provider
search. Existing authenticated read, fresh-admin/CSRF write and explicit search
commands retain their own authority. No schema, dependency, route, worker or
operation-run change is needed. Counts remain private-field-filtered and disappear
after new work/failure through the existing freshness policy.

Validate cause/role/state denial cheaply, then prove capabilities survive the
real detail HTTP and client adapters. Browser evidence must reach the real
destinations by keyboard, refuse links for non-admin/disabled history, preserve
Refresh focus and record no domain mutation during review navigation. Run the
stable fast gate once after focused corrections. Keep packaged Docker readiness
separate from controlled browser and native HTTP evidence.
