# Search again after measured quality review

## Decision

Offer the existing recipient-owned Search again command when measured quality
review is current and no eligible pending/held alternative remains in the entire
current search. Reuse discovery intent, dispatch, audit, command feedback and focus.
Do not create a second search or transfer service.

## Ownership

Extract the preceding alternative-selection scope/policy into a shared small ESM
service. A separate restart guard uses canonical maintenance, account, shared
wanted/discovery, apply-creation and failed-candidate locks. Re-read after waiting;
verify actor privileges, participant eligibility, current search and original
quality floor. Scan candidates in keyset pages, rather than treating the twelve
public choices as proof that alternatives are exhausted.

Commit reset intent, target marker, preserved quality requirement and required
audit together through the existing rediscovery store. Repeated and shared
requests coalesce. Keep the failed candidate, evidence and source bytes intact.
Dispatch happens after durable acceptance and follows saved automation policy.

The requirement stores a quality floor and original participant identity, never
fallback consent. The existing discovery quality resolver applies that floor to
fresh current policy before query construction and ingestion. Current consent
remains its sole owner. Ordinary later retries retain the floor. A changed owner,
participant set, fulfilled/ignored recipient or malformed requirement refuses
dispatch; explicit later quality-fallback consent remains a separate command.
Reconciliation preserves refusal until an explicit new intent, and a captured
claim conditions the terminal write so old work cannot stop a replacement claim.

## Public behavior and evidence

Reuse the native Search again button and accessible command feedback. Describe
accepted intent as queued preparation, not completed discovery or a transfer.
Project queued state for the owning shared intent so failed historical evidence
cannot keep offering the command after acceptance.

Use focused policy/command tests, real SQL/HTTP rollback/replay/contention and
full-search exhaustion cases, then real-app browser focus/refresh checks. Verify
the preserved requirement reaches discovery query and ingestion. Run one stable
fast gate, affected regressions and isolated packaged media checks. Rebuild the
preserved local installation without cache; do not create a release or branch.
