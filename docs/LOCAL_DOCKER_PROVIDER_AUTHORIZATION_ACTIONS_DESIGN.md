# Provider authorization action Docker qualification design

October 28, 2026. See [action design](PROVIDER_AUTHORIZATION_ACTIONS_DESIGN.md) and
the separate [Docker outcome](LOCAL_DOCKER_PROVIDER_AUTHORIZATION_ACTIONS_OUTCOME.md).

Freeze reviewed code, run one complete fast gate and current canonical browser
entries, then build with a disposable pull/no-cache builder. Compare packaged
server/shared/client files, root metadata, dependency and Node identities with the
preceding callback-feedback image. Preserve administrator, five binds, read-only
UID 1000, readiness and loopback port. No additional deployed service.

Use a reusable browser scenario on both a disposable app/PostgreSQL fixture and
the preserved walkthrough. Only four exact authorization POST endpoints receive
controlled local replies. All other API writes are blocked. Controlled settings
GET overlays expose fixture-only linked states without saving them. Record
outgoing CSRF presence/equality without logging token values. Navigate only to an
owned browser-local provider fixture; no external account flow is attempted.

Hold start/clear replies for repeated/cross-action activation, focus and settings
save refusal. Verify fixed failures, explicit subsequent actions, malformed clear,
late response after leaving, acknowledged handoff and safe return. Visual evidence
covers desktop/tablet/mobile in light/dark. Compare actual settings/secret-status
snapshots before/after; controlled command results are not live token publication.

Retain existing native callback/OAuth/Plex authority groups only after exact
unchanged server/shared/package/test comparison. Verify builder/helper retirement
and preserve failed evidence. Private records belong under
`.tmp/provider-authorization-actions-2026-10-28/`. No memory minimum, full quiescence,
native cache restoration or manual accessibility acceptance is implied.
