# Scenario-owned media executor outcome

October 14, 2026. Three modular ESM helpers split current path/argv authorization,
bounded Docker transport and lazy executor lifetime. The explicit distinct/source
benchmark records `--media-execution owned|per-command`; per-command remains its
default. Source no-op and worker-preview native fixtures adopt the optional owner
when an existing media image is configured. Local-tool behavior remains unchanged.

## Implemented boundary

Only the reviewed ffprobe JSON argv can enter the owner. Root identity, current
regular file and real containment are checked before native work. The immutable
image and complete acknowledged container ID bind cleanup authority. Effective
configuration checks include read-only/nonrecursive workspace mount, network none,
read-only root, dropped capabilities, no privilege escalation, no restart, sleep
entrypoint and disabled inherited application health check. Generation retains
its existing per-command path.

The canonical two-file preview starts inspections concurrently. Admission is
bounded to two, with serial native execution and no cross-scenario reuse. The
original thirty-second/two-MiB bounds remain. Failure seals admission, preserves
the first Error/null through queued work and verifies whole-container retirement.
Close shares a promise, drains admitted startup/commands and removes only the
acknowledged stopped owner. The functional app's invocation-specific cleanup guard
retains uncertain workspaces; reusable-app cleanup was not adopted.
Final review added a current root-identity check after container removal: a stopped
owner cannot authorize deleting a replacement directory. A real filesystem control
proves retention. Native owner controls and a complete selected canonical workload
exercise the final close boundary independently of the earlier native cohort.

apply_failed after 8.150 seconds. Source review exposed an incompatible admission
contract: the first executor rejected overlapping inspections while the canonical
preview starts its two file reads together. A bounded serial queue corrected that
contract. Review also found and disabled the image's inherited app health check.
Do not relabel the deadline failure as diagnosed by the later passing owner.

actual source no-op row locks, transaction reuse refusal, write/event rollback,

The earlier unmodified distinct-binding and two delivery-recovery callers passed

## Measurement and scope

The largest noise selections use the same pre-close-refinement freeze, image,
eight bindings, one pair and unchanged pool/deadline policy. Both are incomplete:
the per-command run timed out during seed, after six generated files/thirty
inspections (109,547.581 ms seed, 137.631 s command). The owned run completed
eight generated files/forty inspections (78,532.334 ms seed), then timed out at
the locked-noop sample (116.890 s command). Verified executor close took 2,228.312
ms. Neither published a lone unmatched sample; both reports contain zero samples.
Those unequal completed-work scopes cannot support a speedup percentage or a
passing largest comparison. Returning after cancellation includes actual drainage.

A smaller sine/two-binding/one-pair comparison completed both exact private
result/durable/digest guards, with ten retained inspections/two generated files
per mode. Shared benchmark/generation/SQL code was unchanged between collections;
the final root-close refinement affects only the owned path.

One baseline-first collection is descriptive and cannot establish a full-CI
speedup or diagnose historical failures.

## Recommendations and next item

| Option | Pros | Cons | Recommendation |
| --- | --- | --- | --- |
| Per-command media | Existing conservative lifetime and comparator | Repeated inspection-container startup | Retain as default/comparator during rollout |
| Scenario-owned read-only inspection | Current verification with one inspection-container startup, explicit failure ownership | Bounded queue, configuration/close cost and uncertain-cleanup retention; selected command slower | Retain as explicit opt-in; investigate overhead before promotion |
| Shared writable generator/inspector | Could remove generation startup | Expands write authority and lifetime | Defer; generation unchanged |
| Inspection caching | Removes work | Removes current file verification | Reject for this boundary |

Final recommendation stack: trusted accepted root/image -> acknowledged isolated
read-only owner -> bounded two-file admission/serial current inspection -> verified
retirement/drain/removal -> guarded workspace disposal. Maintain the existing
testing and practical web-standards skills with this method; validation and mirror
checks do not claim a new blind skill trial or standards certification.

Next instrument bounded transport phases to separate Docker CLI/control cost,
actual ffprobe execution and verified close. Evaluate a persistent Engine API
connection only if those observations support it, preserving bounded streams,
every inspection/identity check and exact cleanup authority. Keep the largest
locked-noop timeout as a separate phase investigation. Reversed-order evidence
and cleanup-owner audits precede broader default/reusable-app promotion. See the separate
[design](OWNED_MEDIA_EXECUTOR_DESIGN.md) and
[official October research](OWNED_MEDIA_EXECUTOR_RESEARCH_2026_10.md).
