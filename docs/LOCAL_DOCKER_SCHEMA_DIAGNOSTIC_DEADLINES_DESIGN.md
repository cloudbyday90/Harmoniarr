# Local Docker schema diagnostic deadline validation design

Qualify the frozen October 27 source on main without creating a release or tag.
Keep the established walkthrough administrator, application data and all five
actual bind mounts, including the inspected downloads override. Do not stop
unrelated applications to obtain a quiet run.

## Candidate and runtime checks

1. Run focused ownership/deadline/route/client checks, then one complete fast gate.
   Stage new files and check cached whitespace before freezing the source.
2. Build through a fresh BuildKit builder with pull and no cache; remove that
   builder after load. Compare the immutable image with the previous qualified
   image: only intended server files and rebuilt client assets may differ.
3. Preserve mounts before recreating the existing walkthrough. Verify read-only
   root, UID, loopback publication, existing administrator, 115 applied migrations,
   readiness and removal of the temporary password file/bootstrap helper.
4. Run affected packaged PostgreSQL HTTP, drift/cancellation, ordinary observer
   and preparation serialization fixtures in owned disposable containers: network
   none, read-only root, UID 1000, CPU 2, memory/swap 3 GiB and 256 PIDs. Verify
   actual exit and exact container removal rather than inferring retirement from
   a successful request.
5. Check loaded native-library hashes, entrypoint identity, owned data-bind backup
   publication, live CLI lineage/anchors and existing-administrator browser refresh.
   Browser fixtures separately cover timeout, retry, no-store, status/focus and
   desktop/mobile themes. Manual assistive-technology checks remain deferred.

## Dependency PR and retained scope

Run the selected fixture image's actual server with a disposable file secret,
isolated network and read-only root. Check runtime version, health, refusal without
the key and authenticated application response; retire its exact container and
secret. This does not establish full live-provider/media pipeline qualification.

Retain prior atomic-snapshot, container-replacement and entrypoint preparation
matrices only after exact source/test/runtime review. The raw snapshot, 115
migrations, expected anchor contract, SQL transaction owner, preparation owner,
Dockerfile, dependency lock and entrypoint remain unchanged. A retained matrix
must not be described as a new run.
