## Security, documentation and operational limits

The base environment removes inherited database/parent-control authority and
startup test flags, including case variants, and disables cross-run reuse.
Private shared credentials exist only in the existing shared owner's children;
isolated files receive independent copies of the sanitized base. Native output
remains private evidence; public progress uses file paths, counts and digests.
Original Error/null survives secondary reporting failure. The production
dependency audit reports zero known vulnerabilities; this is not a broad
security certification.

Existing testing and web-standards skills now map complete planning, actual
ownership, final-sink cancellation and prerequisite refusals to concrete modules
and tests. Both repository skills and the installed standards copy validate;
all four installed standards files match. No overlapping skill, new dependency,
production service, schema/migration or release mechanism is introduced.
Opening and final GitHub MCP collection reads returned zero open PRs; no random
or stale PR was available to implement/rebase. No merge or external message
occurred. All changes remain on main, with no release, tag or new branch.

The command deliberately groups the seven reviewed files first, then runs all
others lexically and serially. It stops admission on failure, so incomplete
coverage remains a failed result. The default Node glob remains available.
Source/worker/database authority, configured timeouts and test assertions are
unchanged. Disposable test state does not reserve host CPU. Continue-under-load
validation follows the user's preference; unrelated containers are untouched.
Earlier cold-start failures retain their separate evidence and unknown cause.

## Recommendation stack

Select the opt-in coordinator with complete discovery → canonical exact-once
plan → sanitized environment snapshot → existing fresh shared parent → remaining
isolated serial processes → native root evidence → strict owner release/output
drain → awaited progress → verified complete result.

Benefits: reviewed startup amortization, explicit complete coverage and early
refusal of missing prerequisites or leaked parent authority. Costs: grouped file
order, one larger shared failure scope and strict prerequisites for a full pass.
Complete local correctness evidence alone cannot establish a matched whole-gate
speedup or authorize default promotion; record that decision separately.
