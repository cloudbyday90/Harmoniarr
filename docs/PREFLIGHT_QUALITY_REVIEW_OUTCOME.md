An interrupted audio check uses the existing authenticated prerequisite-recheck command; it queues only after fresh media/file policy passes. More recent preflight events also appear in release-add diagnostics when no apply run exists or an older apply result preceded the stop. Raw gate output, provider paths and sibling policy are excluded.

Production changes use a small ESM preflight-review service and the current prepared-add transaction guard, candidate transition, public projection and UI panel. No schema, dependency, separate application or queue was introduced. Advisory Activity follows committed publication; it is not exactly-once notification delivery.

## Recommendation and boundaries

Adopt actual measurement → current prepared-add guard → atomic bounded stop/audit → scoped static guidance → existing review/recheck command. This preserves ownership and a durable explanation while avoiding known-unsafe queued work. The cost is one short guarded write on a real refusal and careful end-to-end projection/fixture maintenance. The standards and testing AI skills now route to a practical preflight-review reference using the skill-creator guidance.

The SQL/browser gates are deliberately controlled; packaged media proves actual audio measurement separately. This is not public-network acquisition, general authorization/accessibility certification, new deployment memory sizing or real screen-reader/device acceptance. Existing native allocation qualifications are retained from exact unchanged media/runtime comparison; copied/remote effects remain outside SQL rollback.

GitHub MCP returned zero open PRs at initial selection and recheck, so no applicable PR could be implemented or cleaned up. Work remains on main with no release, Git tag or version change.
