# Discover Recommendation Focus Filter Design

Status: Implemented
Date: 2026-06-27
Owner: Product + client architecture

## Scope

Discover now supports a temporary recommendation focus that lets an operator
narrow the recommendation basis to one or more already monitored artists for the
current view. This does not create a second durable recommendation profile and
does not change monitoring, release selection, wanted state, or request state.

## Recommendation

Use validated URL query state for the temporary focus, backed by a small pure ES
module and the existing Discover graph composable.

Selected behavior:

- Query key: `focusArtist`.
- Accepted values: one monitored artist id or repeated query values.
- Invalid ids are dropped after the monitored artist list hydrates.
- An empty focus means "use every monitored artist".
- Filtering is client-side over the already authorized monitored artist
  projection and already fetched recommendation inputs.
- Recommendation cards are recomputed from the focused input result map while
  still excluding all monitored artists from suggested output.
- Controls render as native checkboxes with fixed presentation-copy helpers.

## Alternatives

### URL Query State

Pros:

- Reloadable and shareable.
- Easy to clear without persistent storage.
- Matches existing Harmoniarr grid/filter URL-state direction.
- Keeps the state visible for debugging and browser verification.

Cons:

- Query parameters need validation and cleanup after hydration.
- Multi-value route state is slightly more complex than a local ref.

### Local Component State

Pros:

- Minimal routing code.
- Lowest implementation surface.

Cons:

- Lost on refresh.
- Cannot be deep-linked.
- Harder to verify as a durable browser workflow.

### Server-Side Filter Parameter

Pros:

- Eventually useful if recommendations move behind a ranked server endpoint.
- Can enforce authorization in one place when the server owns ranking.

Cons:

- Premature for the current client-side Discover graph.
- Adds API surface without reducing current data exposure.
- More moving parts for a view-only temporary filter.

## Security Notes

- The filter never requests arbitrary artist data by query id. It only narrows
  ids already present in the authenticated operator's monitored artist
  projection.
- Invalid ids are normalized out before they affect graph state.
- UI copy is generated by fixed helper functions, and Vue text bindings render
  artist names as text, not markup.
- No authorization decision is made in the browser; the server remains
  responsible for authenticated monitored-artist reads.

## Final Stack

- `src/client/lib/discover-recommendation-focus.js` for pure normalization,
  filtering, and route-query construction.
- `useDiscoverGraph()` for focused input state and recomputed suggestions.
- `DiscoverView.vue` for route-query synchronization.
- `DiscoverRecommendationsPanel.vue` for checkbox controls and clear action.
- `discover-presentation.js` for tested labels, helper copy, and summaries.
- Node unit tests for helper, graph, and presentation contracts.
- Playwright browser verification for focus, reload persistence, clear action,
  and keyboard-tab order.

## Outcome

Implemented a temporary, reload-safe Discover recommendation focus that narrows
recommendations by monitored artist without changing durable operator state.
The implementation preserves the core model: all monitored artists are the
default recommendation basis, and focus is only a view-level analysis tool.
