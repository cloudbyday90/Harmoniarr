## Implemented boundaries

Four narrow ESM modules own seed observation, actual media-call observation,
receipt validation and canonical apply/preview capture. The seed observer uses
monotonic intervals and numeric nested spans, awaits optional sinks and preserves
result/Error/null through sink/clock failure. The workload artifact retains a
256-record approved tail and explicit clipping; all values are captured once
before validation. No paths, identifiers, SQL, argv/output or Error payloads are
retained. Shared inspection follows the active context, rather than falsely
labeling later contexts as the first owner.

Wanted distinct fixtures default to the real worker's current accepted preview,
removing only the preparatory preview. The actual worker and operation retain
their source/destination inspection, byte/root/consent checks, durable events,
delivery and returned cleanup. Fixture evidence requires exactly one real worker
preview and a successful apply. The explicit `--seed-preview separate` comparator
remains available for distinct/source modes, and artifact plans record the mode.
Other recovery helper callers retain their original path unless they explicitly
request preview observation. No media inspection or availability cache exists.

Receipt validation moved intact into its own module: actual physical paths and
device/inodes, all saved typed scopes, two owners, contexts and three exact
receipt histories per binding remain. Resource limits, media argv/metadata,
private workspace mounts and network-none commands are unchanged.

The first focused command candidate exposed two ten-second subprocess failures:
invalid arguments and missing GC both imported the full application before
refusal. Lazy ESM imports now follow parsed selection and explicit-GC checks.
The original assertions and subprocess deadlines remain; 17 observer/command
controls then passed in 436.296 ms, and the worker candidate passed in 298.312 ms.
These are separate small runs, not a whole-suite performance comparison.

## Recommendation and next work

Adopt nested owned seed records, actual worker preview capture and lazy command
imports. Pros: fewer redundant inspections, useful partial phase evidence and
cheap early refusal. Costs: diagnostic work, broader helper callers to validate,
and intentional metadata/cache limits. These observations do not establish a
universal timing cap or explain historical failures.

Next select the smallest remaining measured seed bottleneck. Actual inspection
process lifetime/launch cost is a candidate for a scoped owned media executor;
retain every canonical reinspection and per-file metadata. Media batching still
needs independent-file/metadata proof. Defer the
[publication no-change proposal](WANTED_PUBLICATION_NO_CHANGE_PROPOSAL.md) until
fixture lifetime/cost is understood; do not relax final hash/write guards.

The October 14 [owned inspection outcome](OWNED_MEDIA_EXECUTOR_OUTCOME.md) now
implements that candidate as an explicit read-only pilot with bounded concurrent
admission, serial execution and verified container retirement. Its failures and
selected evidence remain separate from this earlier collection.
