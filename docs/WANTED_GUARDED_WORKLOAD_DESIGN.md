# Larger guarded Wanted workload design

October 13, 2026. Baseline main `73e579e`. The reusable reader's isolated
comparison does not measure repeated publication guards. This slice measures
that work before considering another production optimization.

## Measurement boundary

Add an explicit ESM benchmark command, outside automatic integration discovery.
Compare stream/64 KiB and reusable/256 KiB on actual private tagged FLAC, saved
two-owner scopes and real apply completion. Use 16/48/96 historical receipts over
two distinct delivered files, tonal two-second and noise thirty-second media.
These are duplicate historical evidence profiles, not new distinct-track library
coverage. Two alternating pairs per profile yield 24 complete guarded samples.

Each pair uses one borrowed native connection. Each variant runs the actual
direct-mode reconciliation, without a worker lease context, through the
Wanted service, reader, maintenance guard, write/link/event and source-lifecycle
paths inside a fresh rollback-owned transaction. Transaction acquisition/BEGIN/
ROLLBACK, media generation/app setup and explicit pre-sample GC remain outside
elapsed measurement. This measures complete guarded service work before commit;
it does not measure committed publication, scheduling, HTTP or whole-app latency.
Rollback restores baseline rows so variants compare identical private projection
digest sequences, complete result DTOs, query calls and actual hash/byte work.

Report fixed counts/phases, query time, elapsed service time and sampled RSS/heap/
external/ArrayBuffers baseline/peak/delta separately. Count distinct private
root/path bindings and repeated observations per projection without retaining or
publishing paths/IDs/hashes/SQL. Sample memory on a timer, first bytes, each MiB
and completion; sampling overhead and GC/process/cache/order limits remain.
Do not add overlapping memory fields or nested phase totals.

Each pair is its own scenario under the existing 90-second bound. Do not combine
all larger samples into one deadline or increase pool/checkout/scenario limits.
Close query/hash admission on cancellation, await admitted work and actual
scenario completion, then roll back/release/drain before database/files cleanup.
Preserve original Error/null through cleanup; discard an uncertain connection.
CLI summaries remain bounded and private; a failure retains partial completed
measurements without inventing successful results.

## Decision and verification

Keep production hashing, root lookup and every publication reread unchanged.
Repeated path observation is evidence for a future grouping design, not authority
to share positive evidence between guards, owners or invocations. A future design
needs current-path/root/file binding and late-change/refusal proof independently.

Low-level controls cover memory sampling ownership, serial query admission and
original failure/rollback/release. Bounded native controls execute the same
profiling helper, compare actual complete guarded results and preserve late byte
change and required-event rollback. Run the opt-in larger benchmark explicitly;
do not add its minutes to normal validation or infer a universal speedup.

Recommended stack: existing guarded service → same-client rollback measurement →
fresh root/byte checks → fixed work/phase/memory observations → matched private
comparison → scoped design decision. Separate research/outcome documents record
official practices, tradeoffs and actual results. Main only; no release or merge.
