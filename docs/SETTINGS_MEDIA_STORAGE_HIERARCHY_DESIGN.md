# Settings Media & Storage Hierarchy

## Status

Implemented on 2026-07-28.

## Problem

Media & storage placed optional cover-art configuration ahead of folders that
must be valid before Harmoniarr can safely receive and import downloads. Path
validation appeared later as a separate technical card, and the required path
translation action did not reveal the section it changed. This made a normal
local setup harder to scan and diagnose.

## Research

Sources were checked on 2026-07-28 against the requested June 2026 baseline.

| Source | Applied guidance |
| --- | --- |
| [W3C WCAG 2.2 Focus Order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html) | Put required folder controls and their status before optional configuration, preserving a logical visual and keyboard sequence. |
| [W3C ARIA Disclosure Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) | Use semantic buttons with `aria-expanded` and `aria-controls` for optional path translation, secondary folders, artwork, and quota details. |
| [W3C WCAG 2.2 Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) | Keep saved folder-readiness feedback programmatically available without moving focus. |
| [W3C WCAG 2.2 Error Identification](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html) | Pair every non-healthy state with explicit status text and backend-sanitized explanation, rather than relying on color alone. |

## Options Considered

| Option | Pros | Cons |
| --- | --- | --- |
| Keep the existing card order | No UI change | Hides the import prerequisite behind optional artwork and separates troubleshooting from its fields. |
| One large always-expanded settings card | All controls visible | Recreates the busy, high-cognitive-load screen this work is addressing. |
| Required folders first, then named disclosures | Keeps the safe setup path visible, exposes validation near its inputs, and preserves uncommon controls | Requires clear labels and an intentional direct path for setup blockers. |

## Recommendation Stack

1. Present Downloads, Music library, and Staging area first as **Media folders**.
2. Render the saved **Folder readiness** summary and per-folder results directly below those inputs.
3. Keep a missing path translation as a visible setup action; selecting it adds the mapping and opens **Path translations**.
4. Place translations, conversion workspace, per-user folders, cover art, and artwork quota behind named disclosures.
5. Retain server-produced validation and existing import gates. The client only presents validation; it does not infer or rewrite paths.

## Implementation

- Added `SettingsFolderReadiness` to keep root-path health and readable
  messages adjacent to the required folders.
- Added safe presentation helpers that distinguish an unchecked first visit
  from a failed validation and group non-healthy checks for detail disclosure.
- Made `SettingsDisclosure` support controlled open state so an explicit setup
  action opens the relevant form and preserves keyboard/assistive technology
  semantics.
- Reordered Media & storage so optional artwork follows folder setup and moved
  usage telemetry behind a disclosure.

## Security And Data Handling

- Path validation remains generated by the server and is displayed as
  sanitized, operator-facing text.
- Automatic import remains gated by the existing folder/mapping readiness
  checks; this work does not weaken path translation requirements.
- No provider secret, raw service configuration, or filesystem inference is
  exposed by the new presentation.

## Verification

- Focused presentation and disclosure contract tests cover first-visit,
  healthy, and attention states plus setup-action disclosure behavior.
- Browser verification covers Media folders, Folder readiness, and the path
  translation action revealing its target form.
- Client lint/build, full test/build validation, and a no-cache walkthrough
  Docker rebuild are required before completion.
